# 7. รายการข้อมูลที่ยังขาด และการตัดสินใจที่ต้องยืนยัน

ลำดับความสำคัญ: 🔴 ต้องได้ก่อนเริ่ม Phase 2 · 🟠 ต้องได้ก่อน Phase ที่ระบุ · 🟢 ช่วยให้ดีขึ้น
ระหว่างที่ยังไม่ได้ข้อมูล ระบบใช้ค่า "ยังไม่ทราบ" (UNKNOWN/NULL) และ **ไม่เดาค่าแทน**

## A. ระบบ PMS และไฟล์รายงาน

| # | ข้อมูลที่ต้องการ | ทำไมต้องใช้ | ใครให้ได้ | ใช้ใน | ระดับ |
|---|---|---|---|---|---|
| A1 | **ยืนยันระบบ PMS ที่ใช้จริง**: HotelRunner หรือ eZee Absolute — ถ้าย้ายระบบ ย้ายวันไหน | ชื่อรายงานใน requirement และโค้ดเดิมเป็นของ eZee ทั้งหมด; ข้อมูลก่อนวันย้ายอาจต้องอ่านจาก eZee | เจ้าของ | Phase 2 | 🔴 |
| A2 | **ไฟล์ตัวอย่างจริง (CSV/XLSX)** ของแต่ละรายงาน: Night Audit 3 วัน (มีวันที่มี OTA, ยกเลิก/No-show, มัดจำ, คืนเงิน), Monthly Statistics 1 เดือน, Front Desk Activities 3 วัน, Receipt/Payments 3 วัน, Expense Voucher 1 เดือน | สร้างแม่แบบ mapping และกรณีทดสอบ; ปัจจุบันชื่อคอลัมน์ HotelRunner ยังไม่ทราบ | เจ้าของ/พนักงาน (ส่งออกจาก HotelRunner) | Phase 2 | 🔴 |
| A3 | รายชื่อรายงานที่ HotelRunner ส่งออกได้จริงในบัญชีของรีสอร์ต (เมนู PMS › Reports และ Night Audit › Archive) และเลือกฟิลด์อะไรได้บ้าง | กำหนดว่ารายงานไหนเป็น "แหล่งรายได้รายวัน" และ "แหล่งเงินรับ" | เจ้าของ | Phase 2 | 🔴 |
| A4 | HotelRunner มีบันทึกรายจ่าย (paid-out / expense voucher) หรือไม่ ปัจจุบันบันทึกรายจ่ายที่ไหน | ถ้าไม่มี รายจ่ายจะบันทึกในระบบนี้โดยตรง | เจ้าของ | Phase 2–3 | 🟠 |
| A5 | การจอง OTA แบบ OTA Collect (เช่น Expedia) PMS บันทึกราคา **เต็ม** หรือ **สุทธิหลังค่าคอม** | ไฟล์ eZee ตัวอย่างมีราคาสุทธิ (−32.5%) — ถ้าสุทธิ รายได้และค่าคอมในงบจะผิด | เจ้าของ + นักบัญชี | Phase 2 | 🔴 |
| A6 | ความหมายของ folio ใน PMS: 1 การจองมีกี่ folio, split folio, เลข folio ซ้ำข้ามปีได้หรือไม่ | กุญแจกันซ้ำและการจับคู่เงินรับ | ทดสอบจากไฟล์ A2 | Phase 2 | 🟠 |
| A7 | HotelRunner มี API ที่ใช้ได้กับแพ็กเกจปัจจุบันหรือไม่ | นำเข้าอัตโนมัติในอนาคต (credential เก็บฝั่ง server เท่านั้น) | เจ้าของ/HotelRunner | หลัง Phase 8 | 🟢 |

## B. ข้อมูลธุรกิจและบัญชี

| # | ข้อมูลที่ต้องการ | ทำไมต้องใช้ | ใครให้ได้ | ใช้ใน | ระดับ |
|---|---|---|---|---|---|
| B1 | **รายชื่อห้อง** (เลขห้อง ประเภท) — เอกสารบอก 15 ห้อง แอป Android ตั้งค่าเริ่มต้นห้อง 1–16 | จำนวนห้องที่ขายได้ต่อวัน, ตรวจ Night Audit | เจ้าของ | Phase 2 | 🔴 |
| B2 | **รูปแบบกิจการ**: บุคคลธรรมดา / ห้างหุ้นส่วน / บริษัท, เลขผู้เสียภาษี, สถานะ VAT (จดหรือไม่ วันที่จด), ราคาห้องรวม VAT หรือไม่, ใบอนุญาตโรงแรม | VAT ในรายได้, วิธีบันทึกภาษีเงินได้ (เช่น ภาษีเงินได้ของบุคคลธรรมดาเป็นเงินถอนเจ้าของ ไม่ใช่ค่าใช้จ่าย) | เจ้าของ + นักบัญชี | Phase 3, 6 | 🔴 |
| B3 | **ชื่อและช่องทางติดต่อนักบัญชี** และขอบเขตที่นักบัญชีจะยืนยัน | ทุกเรื่องที่ระบุว่า "นักบัญชียืนยัน" | เจ้าของ | ทุก Phase | 🔴 |
| B4 | ยืนยัน **ผังบัญชีร่าง** (`web/db/reference/002_chart_of_accounts.sql`) และ **หมวดรายจ่าย** + treatment (`003_expense_categories.sql`) | การลงบัญชีและงบกำไรขาดทุน | นักบัญชี | Phase 3 | 🔴 |
| B5 | เกณฑ์บัญชี: งบกำไรขาดทุนแบบเกณฑ์คงค้าง (แนะนำ) + รายงานเงินสดแยก; ปีบัญชีเริ่มเดือนไหน | การรับรู้รายได้/ค่าใช้จ่าย | นักบัญชี | Phase 3 | 🟠 |
| B6 | **รายชื่อ OTA ที่ใช้** และเงื่อนไขแต่ละราย: Hotel Collect/OTA Collect, อัตราค่าคอม, ฐานคิด (รวม/ไม่รวมภาษี), วิธีเรียกเก็บ (หักจาก payout/ใบแจ้งหนี้รายเดือน/ตัดบัตร), รอบโอน, ค่าธรรมเนียม/ภาษีบนค่าคอม | `ota_channels`, ค่าคอมประมาณการ, กระทบยอด payout | เจ้าของ (สัญญา/หน้า extranet) + นักบัญชี | Phase 3–4 | 🔴 |
| B7 | **บัญชีเงินทั้งหมด**: ธนาคาร/ประเภท/4 หลักท้าย/วัตถุประสงค์ (รวมกระเป๋า MAKE by KBank — แต่ละกระเป๋ามี statement แยกหรือไม่), รูปแบบ statement ที่ดาวน์โหลดได้ + ไฟล์ตัวอย่าง | `bank_accounts`, แม่แบบ statement | เจ้าของ | Phase 4 | 🔴 |
| B8 | **วันเริ่มใช้ระบบ (go-live)** และ **ยอดยกมา ณ วันนั้น** ที่นักบัญชีรับรอง: เงินแต่ละบัญชี, ลูกหนี้, เงินมัดจำของการจองล่วงหน้า, เจ้าหนี้, เงินกู้คงเหลือ, ทรัพย์สิน (ราคาทุน วันที่ซื้อ อายุใช้งาน), เงินที่เก็บไว้สำหรับร้านแล้ว | `properties.accounting_start_date`, journal OPENING_BALANCE | เจ้าของ + นักบัญชี | Phase 3 | 🔴 |
| B9 | เงินสดหน้าร้าน: มีลิ้นชักเงินสดหรือไม่, ใครนับ, นำฝากธนาคารบ่อยแค่ไหน | `CASH` account, การนับเงินสิ้นเดือน (เงื่อนไขปิดงวด) | เจ้าของ | Phase 3 | 🟠 |
| B10 | ช่องทางรับเงินที่ใช้: เงินสด โอน พร้อมเพย์ บัตร (เครื่อง EDC ของธนาคารไหน ค่าธรรมเนียม) OTA virtual card | แปลงวิธีชำระ → บัญชีเงิน, ค่าธรรมเนียม | เจ้าของ | Phase 2–4 | 🟠 |
| B11 | พนักงาน: จำนวน, วิธีจ่ายเงินเดือน, ประกันสังคม, ภาษีหัก ณ ที่จ่ายเงินเดือน | หมวดเงินเดือนและภาระรายเดือน | เจ้าของ + นักบัญชี | Phase 3, 6 | 🟠 |
| B12 | เงินกู้/ผ่อนชำระ: ผู้ให้กู้ ยอดคงเหลือ ค่างวด วันครบกำหนด ดอกเบี้ย | ภาระผูกพันในแผนเงินทุน | เจ้าของ | Phase 7 | 🟠 |
| B13 | นโยบายค่าเสื่อมราคา (อายุใช้งานแต่ละประเภท) และทะเบียนทรัพย์สินเดิม | ค่าเสื่อมใน P&L | นักบัญชี | Phase 5 | 🟢 |
| B14 | กฎการยกเลิกการจอง/คืนเงิน (แอปเดิม: คืน 50% ของเงินที่จ่าย) ยังใช้หรือไม่ | รายได้ค่ายกเลิก | เจ้าของ | Phase 3 | 🟢 |
| B15 | ข้อมูลในแอป Android เดิม: ย้ายมาหรือเริ่มใหม่ด้วยยอดยกมา (ไฟล์ 02 หัวข้อ 2.9) | ขอบเขตงานย้ายข้อมูล | เจ้าของ | Phase 3 | 🟠 |
| B16 | ระยะเวลาเก็บเอกสารและไฟล์ต้นฉบับ (รวมไฟล์ที่มีข้อมูลแขก) | นโยบายลบ/เก็บไฟล์, PDPA | นักบัญชี | Phase 8 | 🟢 |

| D1 | ผู้ใช้งานและบทบาท (ใครเป็น OWNER, ACCOUNTANT, MANAGER, FRONT_DESK) | สิทธิ์ผู้ใช้ | เจ้าของ | 🟠 Phase 8 (ใช้ทดสอบตั้งแต่ Phase 3) |
