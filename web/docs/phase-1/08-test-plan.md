# 8. Test Plan

## 8.1 กลยุทธ์

| ระดับ | ทดสอบอะไร | เครื่องมือ | เริ่ม Phase |
|---|---|---|---|
| L1 กฎในฐานข้อมูล | constraint, trigger, views (กันซ้ำ, ล็อก, สมดุล, ความครบถ้วน, Audit) | SQL tests `web/db/tests/*.sql` + `run-tests.sh` | **1 (ทำแล้ว)** |
| L2 สูตรการเงิน (unit) | การปัดเศษ, VAT ถอดจากราคารวม, ค่าคอม, เงินที่จัดสรรได้, เดือนถึงเป้า, scenario | pytest + `Decimal` | 3, 6, 7 |
| L3 ตัวอ่านไฟล์ (parser) | แต่ละแม่แบบกับไฟล์ตัวอย่าง: จำนวนแถว, ค่าแต่ละช่อง, ยอดรวม, แถวผิดรูป | pytest + ไฟล์ใน `web/fixtures/` | 2 |
| L4 Integration | นำเข้า → ยืนยัน → ลงบัญชี → รายงาน; กระทบยอดครบวงจร; ปิดงวด | pytest + PostgreSQL จริง (ไม่ mock ฐานข้อมูล) | 2–5 |
| L5 สิทธิ์ผู้ใช้ | ทุกช่องในตาราง RBAC (ไฟล์ 02) ทั้งทำได้และถูกปฏิเสธ (HTTP 403) | pytest (Django test client) | 8 (โครงตั้งแต่ 3) |
| L6 End-to-end UI | หน้าหลักบนมือถือ (390 px) และคอมพิวเตอร์ (1280 px), ภาษาไทย, วันที่ พ.ศ. | Playwright + Chromium | 3–8 |
| L7 ความปลอดภัย | CSRF, session, brute force, อัปโหลดไฟล์อันตราย, secret ไม่อยู่ใน frontend/repo, dependency ที่มีช่องโหว่ | pytest, gitleaks, pip-audit | 8 |
| L8 สำรอง/กู้คืน | dump → restore → เทียบจำนวนแถว → ตรวจกฎยังทำงาน | `tools/backup-restore-drill.sh` | **1 (ซ้อมแล้ว)**, รายเดือนหลัง go-live |
| L9 ประสิทธิภาพ | นำเข้า Night Audit 31 ไฟล์ < 30 วินาที; statement 10,000 แถว; หน้ารายงาน < 2 วินาที | pytest-benchmark / locust | 8 |

**นโยบายข้อมูลทดสอบ**: ใช้ข้อมูลสังเคราะห์ที่ติดป้ายชัดเจน (`TEST_*`, `[TEST]`, `[ทดสอบ]`, อีเมล `@test.local`, `properties.is_sandbox = true`) ในฐานข้อมูลทดสอบที่สร้างใหม่ทุกครั้ง — ไฟล์รายงานจริงที่ได้จากเจ้าของจะถูกลบข้อมูลส่วนบุคคล (ชื่อ เบอร์ เลขการจอง) ก่อนเก็บใน repo; สคริปต์ทดสอบปฏิเสธฐานข้อมูลที่ชื่อไม่มีคำว่า `test`
